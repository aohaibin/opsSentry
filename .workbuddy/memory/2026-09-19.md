### 踩到的三个坑（重要）

1. **antd `Layout` 默认 `flex-direction: column`**，只在有 `<Sider>` 子组件时才自动加
   `ant-layout-has-sider` 转横向。把 `Sider` 换成原生 `<aside>` 后该类消失，内容区被整块
   挤到视口外（表现为右侧一片空白，DOM 里却有内容）。内层 Layout 必须显式
   `flexDirection: "row"`。

2. **`src/main.tsx` 模块顶层裸调 `getCurrentWindow()`**（原有问题）。该函数读
   `window.__TAURI_INTERNALS__.metadata`，在 Tauri webview 之外会抛 TypeError；
   因为是模块顶层，一抛整个入口模块不执行 → 页面全白、React 完全不挂载，极难排查。
   已包 try/catch 降级为 null。

3. **原型导航选中态是 emerald 绿，不是品牌靛蓝**。原型 `switchTab()` 给激活项加的是
   `bg-emerald-500/15 text-emerald-300 border-emerald-500/30`。已用 `--nav-active-*`
   单独建令牌，勿与 `--accent` 合并。

## 追加：servers 模块功能落地情况审计（用户问「服务器里的功能都实现了吗」）

**已落地 9 项**：资产增删改查 + 批量移除；分组/标签/关键词三维过滤；收藏与最近用过（虚拟分组）；
TCP 探活（DNS 失败与端口不可达分开提示）；批量测通/打标签/调策略；SSH 真实认证（密码、私钥，
含主机指纹 TOFU，指纹变化拒绝认证）；远端系统摘要回填 arch；~/.ssh/config 导入；Windows 接入向导。

**注册表副标题宣称但未落地 3 项（文案需要收口，这是当前最该改的点）**：
- SSH-Agent：`ServerService::add/update` 的 `validate_enum("认证方式", ..., &["password","key"])` 只认两种
- ProxyJump 跳板机：`ServerFormModal` 里卡片 disabled「即将支持」，`parse_ssh_config` 也刻意不解析 ProxyJump
- Windows WinRM：Windows 实际走 OpenSSH Server（SSH 协议），与 WinRM 是两套东西

**功能缺口 4 项**：
- 分组只能新建（且必须随主机创建），无重命名/删除
- 表格列未挂 sorter，只有 pageSize=20 分页
- 探活结果只存在 `probeStates` 内存态，刷新即回「未探测」；仅 SSH 认证状态落库
- **审计链路断裂**：`audit_logs` 表 + `commands/audit.rs` 的 get/add 都在，但没有任何一处
  server 服务调用写入 →「全流程不可篡改审计」对 servers 模块目前不成立

**结论**：核心资产与连接能力是真的、可跑通的；缺的是跳板机/Agent/WinRM 三种接入方式、
分组管理、以及审计写入。

## 追加：修复新增服务器保存报错 `missing required key osType`

**症状**：ServerFormModal 点「连通性测试」没反应；保存报
`invalid args 'osType' for command 'add_server': command add_server missing required key osType`。

**根因**：`os_type` 在表单里没有对应的 `Form.Item`（值由上方协议卡片驱动、只写了
`form.setFieldValue`）。而 antd `validateFields()` 只返回**已注册字段**的值
（`getFieldsValue(finalValueNamePathList)`，列表来自 `getFieldEntities(true)`），
所以 `values.os_type === undefined` → `toIpcPayload` 产出 `{ osType: undefined }` →
JSON 序列化丢键 → Rust 侧精确匹配键名失败。
已用 `node_modules/.pnpm/@rc-component+form*/…/es/hooks/useForm.js` 源码确认该行为。

**修复**：
1. `ServerFormModal.tsx`：`handleOk` 里改由 `protocol` state 解析 `resolvedOsType`，
   不再依赖 `values.os_type`（含原因注释）。
2. `src/lib/api/server.ts`：`toIpcPayload` 对 `authType / aiPolicy / osType / group` 加兜底默认值，
   任何新增调用路径都不会再踩同一个坑。
3. 连通性结果条原本渲染在 `max-h-[66vh]` 可滚动区的**最底部**，弹窗里看不见 →
   看起来像「点了没反应」。已移到滚动区之外固定在底部，探测中/失败/延迟都立刻可见。

**验证**：`npx tsc --noEmit` 通过；`npx vite build` 通过（16.70s，EXIT=0）。
浏览器环境无 Tauri 后端，端到端 IPC 仍需用户实机 `pnpm tauri dev` 复测。
注：沙箱下 `pnpm build` 会因 wmic.exe 黑名单被拦，改用 `npx tsc` + `npx vite build`。
